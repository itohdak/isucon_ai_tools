## Hypothesis
`middleware.Logger()` formats and writes a line per request to stdout -> journald (~3.7% of s1 CPU in journald alone, plus formatting inside the app), and `e.Logger.SetLevel(DEBUG)` also enables `c.Logger().Infof` (e.g. one line per reservation slot in `reserveLivestreamHandler`). nginx's LTSV access log already records every request with `reqtime`/`apptime`/status, so the app-side access log is redundant.

## Change
`webapp/go/main.go`: removed `e.Use(middleware.Logger())` (and the now-unused import) and set `e.Logger.SetLevel(echolog.WARN)`. Warnings/errors (`Warnf`/`Errorf` from handlers and the HTTP error handler) are still written to the journal. Observability policy check: the nginx LTSV access log and MySQL slow log (the two permanent, user-mandated sources) are untouched; only the redundant app access log was dropped and this is a normal tracked code change, documented here.
