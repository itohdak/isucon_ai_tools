   - `s1` (app): AMI's default `webapp/` moved aside, git initialized, GitHub deploy key reinstalled from the operator machine's `~/.ssh/isucon_id_rsa`, `origin` added, fetched, checked out `main`, ran `deploy.sh` (`HOSTNAME=s1`), set `env.sh`'s `ISUCON_DB_HOST=192.168.0.12`.

   - `s3` (bench/pprotein, new role): stopped/disabled app-role services and local MySQL (dedicated role, none needed), ran the `general` (Netdata) and `pprotein` ansible roles.
5. **Found and fixed two latent bugs surfaced by the role swap** (both were actually pre-existing, independent of which host played which role — the swap just exposed them for the first time on `s2`):
   - `isucon_ansible/roles/pprotein/tasks/main.yaml`'s "Register ISUCON host aliases" task only looped `groups['pprotein'] + groups['webapp']`, so the `db`-role host's bare hostname never got an `/etc/hosts` entry anywhere. Fixed to include `groups['db']` too.
   - `webapp/go/main.go`'s `collectPprotein()` hardcoded `http://s2:9000/api/group/collect` as its default pprotein-collect URL. Since pprotein moved to `s3`, updated the default to `http://s3:9000/api/group/collect`. Documented in `AGENTS.md` that this default is not derived from ansible inventory or config at runtime, so it must be manually updated (and redeployed) if the bench/pprotein host's label ever changes again.
