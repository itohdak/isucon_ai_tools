## Hypothesis
The tracked nginx config proxied `/api` to `http://localhost:8080` with no upstream keepalive (HTTP/1.0, so a new TCP connection to the app for every request: connect/accept/close syscalls and softirq on the saturated s1) and had no TLS session cache. An upstream `keepalive` pool over HTTP/1.1 and a shared SSL session cache remove that per-request setup.

## Change
`common/etc/nginx/sites-enabled/isupipe.conf` (tracked; `deploy.sh` copies it and restarts nginx): `upstream isupipe_app { server 127.0.0.1:8080; keepalive 256; }`, `proxy_http_version 1.1; proxy_set_header Connection "";`, `proxy_pass http://isupipe_app;`, and `ssl_session_cache shared:SSL:10m; ssl_session_timeout 10m;` in the `u.isucon.local` server. LTSV access logging (`nginx.conf`) untouched. App listens on `*:8080` (IPv4 works).

## Verification
`nginx -t` OK, nginx/isupipe-go active, 3 bench runs pass=true, error categories unchanged.
