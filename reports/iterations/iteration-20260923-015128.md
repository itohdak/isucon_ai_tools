## Problem

The user reported pprotein's slow query log collection wasn't working.

## Root Cause

`pprotein-agent` (running on `s1`) serves `/debug/log/slowlog` by tailing a **local** file, defaulting to `/var/log/mysql/mysql-slow.log` (`integration/integration.go` in the `kaz/pprotein` module, overridable via `PPROTEIN_SLOWLOG`). When MySQL was split from `s1` to a dedicated `s3` host (see `reports/iterations/iteration-20260923-000218.md`), `s1`'s local slow log file stopped receiving new entries, but nothing was changed to serve `s3`'s slow log instead.

Investigation found the central pprotein server's `targets.json` (on `s2`) had **already** been updated (by a prior, uncommitted session) to point a `mysql-s3` slowlog target at `http://s3:19000/debug/log/slowlog` — but `pprotein-agent` itself was never actually deployed to `s3`, so nothing was listening there. `isucon_ansible/roles/pprotein/tasks/main.yaml` only deploys `pprotein-agent` `when: inventory_hostname in groups['webapp']`, and `deploy_pprotein.yaml`'s play only targets `hosts: pprotein:webapp` — the new `db` group (added for `s3` in the previous Netdata-setup iteration) was never in scope for either.

## Change

- `isucon_ansible/playbooks/deploy_pprotein.yaml`: `hosts: pprotein:webapp` → `hosts: pprotein:webapp:db`.
- `isucon_ansible/roles/pprotein/tasks/main.yaml`: the two `pprotein-agent` deployment tasks' `when` condition extended to `inventory_hostname in groups['webapp'] or inventory_hostname in (groups['db'] | default([]))`.
- Ran `ansible-playbook playbooks/deploy_pprotein.yaml --limit s3` to apply immediately (installed `slp`/`alp`/`pprotein` binaries, `pprotein-agent` service, started and enabled it).
- Commit (separate repo): `isucon_ansible` `1e6dead deploy pprotein-agent to the db host too`.
