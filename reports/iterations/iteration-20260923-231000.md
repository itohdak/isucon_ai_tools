## Hypothesis

`moderateHandler` (`livecomment_handler.go`) issues `SELECT * FROM livecomments` with **no WHERE clause**, inside a loop over every NG word registered for the target livestream, then issues one `DELETE` per candidate row (originally emulating `LIKE` via a self-join with the row's own value bound in). This is O(ngwords_for_stream × all_livecomments_system_wide) round trips, and directly explains the 5.5s-avg/11.7s-p99 `/moderate` latency the Profiler Agent found. Scoping the SELECT to `livestream_id = ?` (or better, replacing the SELECT+per-row-DELETE with one `DELETE ... WHERE livestream_id=? AND comment LIKE CONCAT('%',?,'%')` per NG word) is behaviorally identical — the DELETE's own WHERE already filtered by `livestream_id` and the same LIKE comparison, so the final set of deleted rows is unchanged — while cutting round trips from O(ngwords × all comments) to O(ngwords).

## Evidence

- Direct code read (Codex, independently of the App Understanding Agent) confirmed the exact query text: `SELECT * FROM livecomments` with zero WHERE clause, at `livecomment_handler.go` line 393 (pre-fix).
- `journalctl -u isupipe-go` from an earlier iteration's benchmark run showed real `/moderate` calls taking 3.4s-6.1s.
- Profiler Agent (iteration 5): 63 `/moderate` calls, avg 5580.5ms, p99 11722.2ms — worst latency of any route by a wide margin.
- SQL Agent (iteration 5): confirmed `SELECT * FROM livecomments;` (no WHERE) in the raw slow log, `Rows_examined: 1305-1652` per call, `type: ALL` in EXPLAIN.
- `livecomments.comment` is `COLLATE utf8mb4_bin` (confirmed via `SHOW CREATE TABLE` in iteration 1) — a binary/case-sensitive collation, so switching from the self-join LIKE emulation to a direct `comment LIKE CONCAT('%',?,'%')` column comparison preserves identical case-sensitive substring-match semantics (same collation applies either way).

## Change

Rewrote the deletion loop in `moderateHandler`: removed the unscoped `SELECT * FROM livecomments` and the inner per-row DELETE entirely; replaced with one `DELETE FROM livecomments WHERE livestream_id = ? AND comment LIKE CONCAT('%', ?, '%')` per NG word (the outer `ngwords` list was already correctly scoped to the target livestream). `go build`/`go vet`/`gofmt -l` clean.

Files changed: `webapp/go/livecomment_handler.go`.
